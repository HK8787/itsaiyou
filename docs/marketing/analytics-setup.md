# アクセス解析の設定（Cloudflare Web Analytics）

所要時間は5分ほどです。**集客を始める前に入れてください。** 後から入れると、
初動のデータ（どの投稿が効いたか）が取れません。

## なぜ Cloudflare Web Analytics なのか

- **無料**、ページビュー数の上限なし
- **Cookieを使わない**ので、同意バナー（「Cookieを許可しますか」のあれ）が不要
- 個人を特定する情報を集めないので、プライバシーポリシーの記載が軽くて済む
- Google Analytics と違い、広告目的のデータ利用がない

Google Analytics でも計測はできますが、Cookie同意バナーが必要になり、
「無料相談」と身構えている層にとっては入口の印象が悪くなります。

## 手順

### 1. Cloudflare のアカウントを作る

https://dash.cloudflare.com/sign-up

メールアドレスとパスワードだけで作れます。**ドメインの登録は不要です。**
クレジットカードも要りません。

### 2. Web Analytics にサイトを追加する

1. ダッシュボード左のメニューから **Analytics & Logs** → **Web Analytics**
2. **Add a site** をクリック
3. Hostname に `hk8787.github.io` を入力
4. 追加すると、次のようなスニペットが表示されます

```html
<script defer src='https://static.cloudflareinsights.com/beacon.min.js'
  data-cf-beacon='{"token": "abc123def456..."}'></script>
```

### 3. トークンだけを控える

上のスニペットのうち、**`token` の中身（`abc123def456...` の部分）だけ**が必要です。
スクリプトタグ全体をコピーする必要はありません。

### 4. サイトに設定する

`src/data/site.ts` の `analyticsToken` に貼り付けます。

```ts
analyticsToken: process.env.NEXT_PUBLIC_CF_BEACON_TOKEN || "ここにトークン",
```

コミットしてmainにマージすれば、次のデプロイから計測が始まります。

> トークンは秘密情報ではありません。計測タグとしてブラウザに配信される値なので、
> ソースコードに直接書いても問題ありません。

### 5. 確認

デプロイ後、サイトを何ページか閲覧してから Cloudflare のダッシュボードを見ると、
数分でアクセスが反映されます。

## 何が分かるか

| 指標 | 使いどころ |
|---|---|
| ページビュー / 訪問者数 | 全体の流入量 |
| **Referrers（参照元）** | X・Google・直接のどれが効いているか。**ここが一番重要** |
| Top pages | どの記事が読まれているか。次に書く記事の判断材料 |
| 国・デバイス | スマホ比率。ほぼスマホのはず |

## LINEの友だち追加数はどこで見るか

Cloudflare Web Analytics ではボタンのクリック数は取れません。
ただし **LINE公式アカウントの管理画面**に友だち追加数の推移が出るので、
そちらを見てください。

- サイトのアクセス数（Cloudflare）
- LINEの友だち追加数（LINE公式アカウント管理画面）

この2つを並べれば、「何人来て何人が相談に進んだか」が分かります。

## 補足：ボタンのクリックを個別に計測したくなったら

`/line/` のような中継ページを作り、LINEボタンの飛び先をそこにして、
そのページから本物のLINE URLへ転送する方法があります。
中継ページの閲覧数＝ボタンのクリック数として計測できます。

ただし表示が一瞬挟まるぶん体験は悪くなります。
相談の件数がある程度増えて、流入元ごとの精度が必要になってから検討してください。

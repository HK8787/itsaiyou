# 集客のやり方

サイトを公開しただけでは誰も来ません。ここに、何をどこで発信するかをまとめます。

---

## 1. 大前提：出せる広告と、出せない広告

**出せません**

- Indeed・求人ボックス・スタンバイ等への求人出稿
  → 求人広告を出せるのは求人企業本人か、許可を持った職業紹介事業者だけです。
    運営者はどちらでもないので、自分名義で「エンジニア募集」は出せません。

**出せます**

- 「IT転職の無料キャリア相談やってます」という **相談窓口としての告知**
- 自分の体験談・業界の解説などの **コンテンツ発信**

サイトもこの前提で「求人広告サイト」ではなく「相談窓口＋求人はモデルケース提示」という
構成にしてあります。発信も同じ線を守ってください。

---

## 2. 発信者としての立ち位置

運営者の経歴です。**発信の信用は、全部ここから出ます。**

| 時期 | 内容 |
|---|---|
| 3年半 | 調理の仕事 |
| — | **未経験でIT業界へ** |
| うち約1年はリーダー | ヘルプデスク |
| 現職・IT歴4年 | SAPコンサルタント |

保有資格：応用情報技術者、基本情報技術者、ITパスポート、G検定、Google広告認定、調理師

**資格は前に出さないでください。** 読者は応用情報が何かを知りませんし、
肩書きを頭に置いた瞬間に「向こう側の人」になります。
経歴を読んだあとの裏付けとしてだけ効きます。順番を守ってください。

### この経歴が、このサイトにとって最強の資産である理由

ターゲットは **「自分なんてIT業界とは無縁だ」と思って選択肢から外している人**、
つまり今まさに飲食・接客・製造・販売にいる人です。

その人たちから見ると、

- 「IT4年目のSAPコンサル」 → **向こう側の住人**。参考にならない
- 「元調理師でIT4年目」 → **数年後の自分**。話を聞きたい

同じ人物でも、どちらを先に出すかで届く相手が変わります。
**調理の3年半を削らないでください。** そこが入口です。

### 言えること／言えないこと

**言えること**

- **「未経験からIT」を体験談として書ける。** 当事者です。ここは騙りではありません
- **ヘルプデスクの現場を知っている。** 当サイトが未経験者に勧める職種そのものです。
  仕事の中身、1日の流れ、最初の数ヶ月がどうだったかを実体験で書けます
- **リーダーとして未経験者を見てきた。** 入る側と受け入れる側、両方の視点があります
- **基本情報・応用情報を持っている。** 未経験者が最初に目指す資格そのものなので、
  「取る意味があるのか」「働きながらどう勉強したか」に実体験で答えられます。
  肩書きとして掲げるのではなく、**勉強法の話の中身として使ってください**
- **異業種転職の当事者。** 「辞めるのが怖い」「周りに反対される」といった
  感情の部分に、経験として答えられます

**言えないこと**

- **開発エンジニアではありません。** コードを書く仕事の体験談は書けません。
  WEBエンジニア志望者向けの話は「調べた事実」として書いてください
- 支援実績の数字（まだ実績がありません）

見てきたことと調べたことを分けて書く。守るのはこの一線だけです。

ターゲットは **「自分なんてIT業界とは無縁だ」と思って選択肢から外している人**。
これを外さないでください。

## 3. チャネルの優先順位

初期は「見てもらえるかどうか」で決めます。
フォロワー0のアカウントは、投稿してもほぼ誰にも表示されません。

| チャネル | 初期の露出 | 寿命 | コスト | 立ち上がり |
| --- | --- | --- | --- | --- |
| **Yahoo!知恵袋** | ◎ 最初から読まれる | 数年 | 0円 | **即日** |
| note | ○ | 長い | 0円 | 1ヶ月〜 |
| X（旧Twitter） | △ 初期はほぼゼロ | 数時間 | 0円 | 1〜3ヶ月 |
| ブログ/SEO | △ | 長い | ドメイン代 | 6ヶ月〜 |
| Meta広告 | ◎ | 止めたら終わり | 月3万円〜 | 即日 |

### 知恵袋を最優先にする理由

- **フォロワーの蓄積が要らない。** 最初の回答から人が読みます
- 質問者は今まさに困っている人。温度がまったく違います
- 回答が検索結果に残るので、**数年間読まれ続けます**
- この領域は雑な回答か露骨な宣伝しか付いていないことが多く、勝ちやすい

やり方と回答テンプレは `chiebukuro.md` にまとめてあります。

### Xは「並行して仕込む」もの

即効性はありませんが、続けていれば効いてきます。
知恵袋で回答しながら、1日1投稿を積んでおく形が現実的です。

### 広告は最後

流入の形が見えてから。いま出しても、どこを改善すべきか判断できません。

## 4. 最初の90日でやること

### Week 1：土台（ほぼ完了済み）

- [x] サイトをデプロイ（docs/DEPLOY.md）
- [x] LINE公式アカウント開設 → 友だち追加URLを `site.ts` に反映
- [x] 相談フォームの送信先を設定（docs/marketing/form-setup.md）
- [x] アクセス解析を有効化（docs/marketing/analytics-setup.md）
- [ ] **Search Consoleに登録 → サイトマップ送信**（docs/marketing/search-console.md）
- [ ] 知恵袋アカウント作成 → プロフィールにサイトURL
- [ ] Xアカウント作成 → プロフィールと固定ポストを設定

Search Consoleが未登録のあいだは、「ゼロイチIT」で検索しても
サイトが出てきません。知恵袋やXで屋号を見た人が検索して何も出ないのは
機会損失なので、ここを先に潰してください。15分で終わります。

### Week 2〜12：毎日まわす

- **知恵袋に1日2〜3件回答**（`chiebukuro.md`）。これが主軸
- **noteに週1本投稿**（`note-articles.md` に4本、1ヶ月分の在庫あり）
- **Xに1日1投稿**（`x-posts.md` に約25本、1ヶ月弱の在庫あり）
- 補足質問・リプライには必ず返す。ここが一番相談につながります
- 月1〜2本、サイトの未経験ガイドに記事を足す

### 目標の目安

| 指標 | 1ヶ月後 | 3ヶ月後 |
| --- | --- | --- |
| 知恵袋の回答数 | 40〜60件 | 150〜200件 |
| サイト訪問者 | 50〜150 | 300〜800 |
| LINE友だち追加 | 1〜5件 | 5〜20件 |
| 提携先への取次ぎ | 0〜2件 | 2〜8件 |

**最初の1件が出るまでが一番きついところです。**
数字が動かない期間が1ヶ月以上続きますが、それが普通です。
ここで辞める人が大半なので、逆に言えば続けるだけで残れます。

判断材料はアクセス解析の Referrers を見てください。
「どこから来ているか」が分かれば、続けるべきチャネルが分かります。

## 5. 言ってはいけないこと

発信でこれをやると、景品表示法・職業安定法に触れる可能性があります。

**断定・誇大表現はNG**

- ✕「絶対に転職できます」「必ず年収◯◯万円になれます」
- ○「〜のケースが多いです」「〜を狙える可能性があります」

**実績・経歴の捏造はNG**

- ✕ 支援実績がないのに「支援実績100名」と書く
- ✕ 開発経験がないのに「エンジニアとして開発をしていました」と書く
- ○ ヘルプデスク・SAPの経歴はそのまま書いてよい（事実です）
- ○ 実績の数字は、出てから書く

経歴の詐称は、発信を続けるほど矛盾が増えて必ず崩れます。
**持っているものは書く、持っていないものは書かない。** これだけです。
実務経験があるぶん、盛る必要はありません。

**紹介料の関係で嘘をつかない**

紹介料などお金の話は、サイト・プロフィール・回答・LINE・SNSのどこにも自分からは書きません。
聞かれたときだけ、正直に答えてください。
「紹介料はもらっていない」のような否定や、ごまかしはしないこと。
知恵袋などで「窓口をやっている」と立場を書いておくのは続けてください。

**求職者から金銭を受け取らない**

職業安定法で原則禁止です。「有料のキャリア相談」「情報商材」に寄せた瞬間に別の話になります。
このモデルは求職者無料が前提です。

## 6. 提携先のサポート内容と、提案での使い方

2026年9月に提携先（合同会社H CAREER）から受け取った紹介文の要点です。
サイトでは `src/data/support.ts` にまとめてあり、トップ・FAQ・`/about` から読んでいます。

| 項目 | 内容 |
| --- | --- |
| 扱う求人 | **正社員のみ** |
| 職種 | **ITに限らない。** 多彩な業界・職種 |
| 求人数 | 全国20万件以上（**提携先の公表値**） |
| 体制 | 専任の3名チーム |
| 対応時間 | **土日祝・平日夜間も対応** |
| 書類 | 履歴書・職務経歴書を何度でもブラッシュアップ。求人ごとに文章を修正 |
| 面接 | 企業ごとの面接傾向を共有。模擬面接あり |
| 費用 | 完全無料。納得いくまで何度でも |
| サポート開始 | **入社希望月の3か月前から**（4月入社なら1月から） |

### 取次ぎの流れ

1. 候補者がヒアリング項目を記入 → 2. 本人の了承を取って、提携先とのグループトークに共有し支援可否を確認
→ 3. 支援可能なら提携先が候補者用グループを作りIDを発行、こちらが公式LINEで候補者に伝える
→ 4. 候補者がグループに参加して支援開始。

LINE公式アカウントはグループ作成・招待ができないため、この形になっています。
文面は `line-templates.md` の5章にあります。**ステップ2の前の了承取りを飛ばさないこと。**

### これで何が変わったか

これまでは「ITに向かない人」「電気や設備など別の道が合う人」には、
情報提供しかできませんでした。**今は、その人たちもそのまま繋げます。**

- 製造業から電気・設備管理に行きたい人 → 設備管理の正社員求人を探してもらえる
- 事務・営業事務を希望している人 → IT以外も含めて並べて比べられる
- 地方在住の人 → 全国が対象

ITを軸にしていることは変えません。屋号も3ルートもそのままです。
ただ、**「ITじゃないなら扱えない」とは言わなくていい**、ということです。

### 知恵袋・LINEで言っていいこと

- ○「LINEで気軽に相談できますし、条件に合う求人も見られます」
- ○「IT以外も含めて、正社員の求人を探せます」
- ○「土日や平日の夜でも相談できます」
- ○「書類は応募する求人ごとに直してもらえます。模擬面接もあります」

**「エージェントに繋ぐ」「エージェントさんにお繋ぎします」は、知恵袋の回答では使わない。**
読み手が「結局は業者に回されるのか」と身構えるためです。
入口は「LINEで相談できる」「求人も見られる」と書いてください。
提携先の存在は、LINEでやり取りが始まってから、取次ぎの段階（line-templates.md 5章）で伝えれば足ります。

### 言ってはいけないこと

- ✕「福岡に◯◯の求人があります」
  → **あるかどうかは探すまで分かりません。**「探してもらえます」まで
- ✕「20万件あるので必ず見つかります」
  → 件数は提携先の公表値で、見つかることの保証ではありません
- ✕ 20万件を出典なしで書く
  → 書くなら「提携先の取り扱いは全国20万件以上とのことです」と出典つきで
- ✕「私が求人を紹介します」
  → 紹介するのは提携先です。こちらは「おつなぎします」

### 数字や対応範囲が変わったら

`src/data/support.ts` を直せばトップの表示が変わります。
FAQ（`src/data/faq.ts`）と `/about` の文言にも同じ数字が入っているので、あわせて直してください。

## 7. 知恵袋の回答ルール

実際に回答を重ねる中で決まったルールです。回答を作るときはここを基準にしてください。

**誘導の出し方（2026年10月に変更）**

本文で「LINEで送ってください」「エージェントさんにお繋ぎします」「条件に合う求人も見られます」と
書いた回答が、運営に2件削除されました。宣伝・勧誘／外部への誘導と判断されたと考えられます。
短い期間に削除が重なると1週間の利用停止、さらに重なると知恵袋そのものが使えなくなります
（カテゴリマスターも失います）。なので、本文での誘導は**最後の一言だけ**にします。

- **1通目の締めは、この一言だけ：**「プロフィールに、相談窓口の情報を載せています。」
- 本文に書かない言葉：**LINE／エージェント／お繋ぎ／求人が見られる／送ってください**
- 区切り線を引いて「ここから立場を明かします」のようなブロックも作らない
- **2通目以降・補足・お礼への返信**で、向こうから「相談したい」「どうすればいい？」と聞かれたら、
  そこで初めて「プロフィールのサイトからLINEで相談できます」と案内してよい
- 回答の中身で信頼を取るのが本筋。ベストアンサーとカテゴリマスターが、プロフィールを開いてもらう理由になります

**時期の話（提携先のサポートは入社希望月の3か月前から）**

- 回答で時期に触れるときは、これと食い違わないようにする
  - 早めの入社（年明けなど）を狙える人には、そちらを提案する（冬のボーナス後の退職と両立しやすい）
  - 入社が先の人には「それまでに方向決めや書類の準備を進めておくと、本番で慌てずに済みます」のように、本文の中身として書く
- LINEでのやり取りに入ってからは、`line-templates.md` のとおり、見込みのある人は待たせずに進める

**URLは絶対に書かない**

知恵袋は `http` を含む投稿を保存できません。プロフィールのサイト欄だけが出口です。

**長さ**

1,000〜1,500字。ベストアンサーに選ばれやすい長さです。
短い補足への返信は、相手の文量に合わせて短くしてください。

**見送る質問**

- 医療・支援機関の領域（メンタル不調による休職など、まず医療側の話になるもの）
- こちらが「今は動かないほうがいい」と助言する相手
- 2回やり取りして見込みがなければ、それ以上は追わない

以前は「資格職で方向が固まっている人」も見送り枠でしたが、
6章のとおりIT以外も繋げるようになったので、**見送り枠から外しました。**

**求人・エリアの約束をしない**

「◯◯の求人があります」「◯◯県も紹介できます」は書かない。
「条件を伺ったうえで、あるかないか正直にお返しします」で統一してください。

**書き方**

- 経歴は「調理3年半 → 未経験でIT → ヘルプデスク（うち約1年リーダー）→ SAPコンサル、IT歴4年」の順
- 資格は前に出さない（2章）
- 相手の状況を「自分と同じ」と決めつけない。人それぞれです
- LINE上では知恵袋のIDで呼ばない。LINEの表示名で呼ぶ

## 8. イチニキャリア（2回目・3回目の転職向け）

ゼロイチIT（0→1：未経験から最初の一歩）の姉妹ブランドです。
**1→2：経験を武器に、年収とキャリアを上げる転職**を相談する窓口として、同じリポジトリ内に作っています。

**URL**

- トップ：`/ichini/`（GitHub Pages では https://hk8787.github.io/itsaiyou/ichini/ ）
- 年収アップ診断：`/ichini/shindan/`
- 求人の例：`/ichini/jobs/`

**共通のもの・分けたもの**

| | ゼロイチIT | イチニキャリア |
|---|---|---|
| 対象 | 未経験・学歴不問・最初の転職 | 2回目・3回目、経験者の年収アップ |
| デザイン | 青・ゴシック体 | 黒 × 金・見出しは明朝体。飾りは使わず、罫線と余白で見せる |
| LINE公式 | 共通 | 共通 |
| 運営者・提携先 | 共通 | 共通 |
| プライバシーポリシー | `/privacy/` | 同じページを使う |

**誘導の使い分け**

- 知恵袋のプロフィールのリンクはゼロイチITのまま。ゼロイチITのフッターからイチニキャリアに行けます
- 経験者の質問（2回目以降・年収アップ・転職回数が多い）には、回答の中で「プロフィールのサイトから、経験者向けの年収アップ診断もできます」と添えてよい
- 診断の結果はコピーしてLINEに貼れるようになっています。結果が届いたら、ふだんどおり事前ヒアリング項目（`line-templates.md` §1）を送ってください

**書いてはいけないこと（景品表示法）**

- 「平均◯万円アップ」「年収アップ率◯%」などの実績の数字。集計した実績がないので根拠を示せません
- 診断も金額は出さず、「余地が大きい／十分ある／組み立て次第」の3段階と動き方だけを返しています
- 求人の例の年収は**モデルケースの幅**です。実在の求人のように書かないこと

**文面を変えるとき**

- 文言・求人の例・FAQ：`src/data/ichini.ts`
- 診断の質問と結果：`src/components/ichini/Diagnosis.tsx`
- 配色とフォント：`src/app/globals.css` の「イチニキャリア専用のトーン」、`src/app/ichini/layout.tsx`
- ボタンや見出しなどの部品：`src/components/ichini/ui.tsx`（LINEボタンも緑ではなく金。文言に必ず「LINE」を入れる）
- **飾りを足さないこと。** ローマ数字・字間の広い英字・◆の飾り罫・金のグラデーション文字・ぼかした光を入れた版は「AI感が強い」と言われて外した。理由は ui.tsx 冒頭のメモ
- OGP画像（SNSで共有したときの画像）は未作成です。作るまでは画像なしで表示されます

### ⚠️ 候補者の個人情報について

**このリポジトリは公開です。** GitHub上の全ファイルを誰でも閲覧できます。

`candidates.csv` は列の設計を示す雛形であり、**実データを書き込まないでください。**
氏名・年齢・学歴・在職状況は個人情報です。公開リポジトリに載せた時点で
取り返しがつきません（コミット履歴に残るため、後から消しても復元できます）。

実際の管理には、次のどちらかを使ってください。

1. **Googleスプレッドシート**（推奨）
   `candidates.csv` をそのままインポートすれば、列がそのまま使えます。
   共有設定は「制限付き（自分のみ）」にすること。
2. **ローカルのファイル**
   `candidates-real.csv` のような名前で保存してください。
   この名前は `.gitignore` に登録済みなので、誤ってコミットされません。

あわせて、サイトのプライバシーポリシーに書いた内容と、実際の扱いが
食い違わないようにしてください（`src/app/privacy/page.tsx`）。

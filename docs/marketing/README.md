# 集客のやり方

サイトを公開しただけでは誰も来ません。ここに、何をどこで発信するかをまとめます。

---

## 1. 大前提：出せる広告と、出せない広告

**出せません**

- Indeed・求人ボックス・スタンバイ等への求人出稿
  → 求人広告を出せるのは求人企業本人か、許可を持った職業紹介事業者だけです。
    運営者はどちらでもないので、自分名義で「エンジニア募集」は出せません。

**出せます**

- 「IT転職の無料キャリア相談やってます」という **相談窓口としての告知**
- 自分の体験談・業界の解説などの **コンテンツ発信**

サイトもこの前提で「求人広告サイト」ではなく「相談窓口＋求人はモデルケース提示」という
構成にしてあります。発信も同じ線を守ってください。

---

## 2. 発信者としての立ち位置

運営者はエンジニアではなく、**未経験向けの求人情報を調べて整理し、
希望者を提携先へおつなぎする窓口**です。ここを偽らないでください。

「未経験からITに入って現場にいる人」を名乗れば刺さりやすくはなりますが、
その前提で発信を始めると、経歴の話が出るたびに嘘を重ねることになります。
深掘りされた瞬間に崩れ、そこまで積んだ信用が全部なくなります。

軸はこれです。

> 未経験の人が知りたいことを調べて整理し、事実として書く

「体験した人」ではなく「**調べた人**」として書けば、嘘はゼロで済みます。
そして未経験者が本当に困っているのは、体験談ではなく
「職種の違い」「手取りの額」「面接の答え方」といった**情報**のほうです。

ターゲットは **「自分なんてIT業界とは無縁だ」と思って選択肢から外している人**。
これを外さないでください。

---

## 3. チャネルの優先順位

初期は「見てもらえるかどうか」で決めます。
フォロワー0のアカウントは、投稿してもほぼ誰にも表示されません。

| チャネル | 初期の露出 | 寿命 | コスト | 立ち上がり |
| --- | --- | --- | --- | --- |
| **Yahoo!知恵袋** | ◎ 最初から読まれる | 数年 | 0円 | **即日** |
| note | ○ | 長い | 0円 | 1ヶ月〜 |
| X（旧Twitter） | △ 初期はほぼゼロ | 数時間 | 0円 | 1〜3ヶ月 |
| ブログ/SEO | △ | 長い | ドメイン代 | 6ヶ月〜 |
| Meta広告 | ◎ | 止めたら終わり | 月3万円〜 | 即日 |

### 知恵袋を最優先にする理由

- **フォロワーの蓄積が要らない。** 最初の回答から人が読みます
- 質問者は今まさに困っている人。温度がまったく違います
- 回答が検索結果に残るので、**数年間読まれ続けます**
- この領域は雑な回答か露骨な宣伝しか付いていないことが多く、勝ちやすい

やり方と回答テンプレは `chiebukuro.md` にまとめてあります。

### Xは「並行して仕込む」もの

即効性はありませんが、続けていれば効いてきます。
知恵袋で回答しながら、1日1投稿を積んでおく形が現実的です。

### 広告は最後

流入の形が見えてから。いま出しても、どこを改善すべきか判断できません。

## 4. 最初の90日でやること

### Week 1：土台（ほぼ完了済み）

- [x] サイトをデプロイ（docs/DEPLOY.md）
- [x] LINE公式アカウント開設 → 友だち追加URLを `site.ts` に反映
- [x] 相談フォームの送信先を設定（docs/marketing/form-setup.md）
- [x] アクセス解析を有効化（docs/marketing/analytics-setup.md）
- [ ] 知恵袋アカウント作成 → プロフィールにサイトURL
- [ ] Xアカウント作成 → プロフィールと固定ポストを設定

### Week 2〜12：毎日まわす

- **知恵袋に1日2〜3件回答**（`chiebukuro.md`）。これが主軸
- **noteに週1本投稿**（`note-articles.md` に4本、1ヶ月分の在庫あり）
- **Xに1日1投稿**（`x-posts.md` に約25本、1ヶ月弱の在庫あり）
- 補足質問・リプライには必ず返す。ここが一番相談につながります
- 月1〜2本、サイトの未経験ガイドに記事を足す

### 目標の目安

| 指標 | 1ヶ月後 | 3ヶ月後 |
| --- | --- | --- |
| 知恵袋の回答数 | 40〜60件 | 150〜200件 |
| サイト訪問者 | 50〜150 | 300〜800 |
| LINE友だち追加 | 1〜5件 | 5〜20件 |
| 提携先への取次ぎ | 0〜2件 | 2〜8件 |

**最初の1件が出るまでが一番きついところです。**
数字が動かない期間が1ヶ月以上続きますが、それが普通です。
ここで辞める人が大半なので、逆に言えば続けるだけで残れます。

判断材料はアクセス解析の Referrers を見てください。
「どこから来ているか」が分かれば、続けるべきチャネルが分かります。

## 5. 言ってはいけないこと

発信でこれをやると、景品表示法・職業安定法に触れる可能性があります。

**断定・誇大表現はNG**

- ✕「絶対に転職できます」「必ず年収◯◯万円になれます」
- ○「〜のケースが多いです」「〜を狙える可能性があります」

**実績・経歴の捏造はNG**

- ✕ 支援実績がないのに「支援実績100名」と書く
- ✕ エンジニア経験がないのに「未経験から入って現場にいます」と書く
- ○ 実績が出てから、事実だけ書く

経歴の詐称は、発信を続けるほど矛盾が増えて必ず崩れます。
「調べて書いている人」として通すほうが、長期的に強いです。

**紹介料の関係は隠さない**

ステルスマーケティング規制（景表法）の対象になります。
サイトの `/about` には既に明記してあるので、SNSでも聞かれたら正直に答えてください。
むしろ先に開示したほうが信用されます。

**求職者から金銭を受け取らない**

職業安定法で原則禁止です。「有料のキャリア相談」「情報商材」に寄せた瞬間に別の話になります。
このモデルは求職者無料が前提です。

## 6. ファイル一覧

- `note-articles.md` … note投稿用の記事4本。全文書き上げ済み、貼るだけです
- `x-posts.md` … X投稿の下書き25本。空欄なし、そのまま投稿できます
- `line-templates.md` … 友だち追加後〜取次ぎまでのLINE返信テンプレ

**提携先**

- `partner-questions.md` … 提携先へ事前確認しない方針とその前提。方針を変える場合の文面も収録

**設定**

- `form-setup.md` … 相談フォームの送信先（Google Apps Script）の設定手順
- `gas-form-receiver.gs` … 上記に貼り付けるスクリプト本体
- `analytics-setup.md` … アクセス解析（Cloudflare Web Analytics）の設定手順

**管理**

- `candidates.csv` … 候補者管理シートの**雛形**

### ⚠️ 候補者の個人情報について

**このリポジトリは公開です。** GitHub上の全ファイルを誰でも閲覧できます。

`candidates.csv` は列の設計を示す雛形であり、**実データを書き込まないでください。**
氏名・年齢・学歴・在職状況は個人情報です。公開リポジトリに載せた時点で
取り返しがつきません（コミット履歴に残るため、後から消しても復元できます）。

実際の管理には、次のどちらかを使ってください。

1. **Googleスプレッドシート**（推奨）
   `candidates.csv` をそのままインポートすれば、列がそのまま使えます。
   共有設定は「制限付き（自分のみ）」にすること。
2. **ローカルのファイル**
   `candidates-real.csv` のような名前で保存してください。
   この名前は `.gitignore` に登録済みなので、誤ってコミットされません。

あわせて、サイトのプライバシーポリシーに書いた内容と、実際の扱いが
食い違わないようにしてください（`src/app/privacy/page.tsx`）。

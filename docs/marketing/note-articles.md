# note 投稿用の記事（そのまま貼れます）

## できること・できないこと

**投稿の代行はできません。** noteはアカウント作成もログインも投稿も
ブラウザ操作が必要で、個人向けの投稿APIもありません。
認証情報を預かるのも避けるべきなので、そこはご自身でお願いします。

**記事はここに書き上げてあります。** コピーして貼り、公開を押すだけです。

---

## 重要：サイトの記事をそのままコピーしないでください

同じ本文が2箇所にあると、検索エンジンがどちらを評価するか割れます
（重複コンテンツ）。せっかくサイトに記事があるのに、
noteに食われて自サイトが表示されなくなる、ということが起こりえます。

そこで、以下の4本は**すべて切り口を変えて書き直してあります。**
サイトの記事とは別物なので、両方出して問題ありません。

各記事の末尾にサイトへの導線を置いてあります。
noteで読んだ人が、より詳しい情報を求めてサイトに来る形です。

---

## 投稿の設定

| 項目 | 設定 |
|---|---|
| 記事の種類 | テキスト |
| 価格 | **無料**（有料にしないでください。職業安定法上、求職者から金銭を受け取るのは原則禁止です） |
| 公開範囲 | 全体に公開 |
| 投稿頻度 | 週1本。4本あるので1ヶ月もちます |

**ハッシュタグ**（各記事の末尾に記載のものを使ってください）

noteはハッシュタグからの流入が大きいので、必ず3〜5個つけてください。

**見出しの設定**

`##` の行は、noteのエディタで「見出し」に設定してください
（テキストを選択 → ツールバーの H）。
そのまま `##` を残すと記号が表示されてしまいます。

# 記事1

## タイトル

```
「未経験からIT」で調べた人が、最初に知るべきだったこと
```

## 本文

「未経験 IT 転職」で検索すると、記事が大量に出てきます。
ただ、そのほとんどが「ITエンジニア」をひとくくりにして書いている。

ここが最初のつまずきどころです。

ITエンジニアと呼ばれる仕事は、中身がまったく違う職種の集まりです。
そして**未経験からの入りやすさが、職種によって全然違います。**

同じ「未経験可」でも、すんなり入れるところと、
半年準備しないと土俵に立てないところがある。
これを知らないまま動くと、いちばん難しい入口に正面から突っ込むことになります。

調べた結果を整理します。

## 未経験の入口として現実的な職種

### インフラエンジニア（サーバー・ネットワーク）

ITサービスが動き続けるための土台をつくり、守る仕事です。

未経験求人がもっとも多いのがここ。そして重要なのが、
**入社したその日から実務経験としてカウントされる**という点です。

最初は「運用監視」から始まり、経験を積んで「構築」「設計」へ上がっていく。
これが定番の流れです。

注意点として、夜勤を含むシフト勤務の求人が一定数あります。
日勤固定もありますが、数は限られ競争率が上がります。

### ヘルプデスク・ITサポート

社内やお客様のPC・システムのトラブルに対応する仕事。

**心理的ハードルが一番低い入口**です。
接客・販売・コールセンターの経験がそのまま強みになります。

ただし正直に書くと、ITスキルは伸びにくいポジションです。
ここに入るなら「数年で次に進む」前提で計画を立てたほうがいい。
10年いると、逆に動けなくなります。

### テストエンジニア（QA）

作られたシステムが仕様どおり動くかを検証する仕事。
細かい作業を淡々と正確に進められる人に向いています。

開発の流れを間近で見られるので、そこから開発職へ移る人もいます。

### Salesforceエンジニア

企業の営業・顧客管理を支えるクラウドサービスの設定・開発を行う専門職。

扱える人が国内で足りておらず、**資格がそのまま市場価値になります。**
準備期間は長め（6〜9ヶ月）ですが、数年後の年収レンジがいちばん高い領域です。

## 学習期間を挟めば狙える職種

### WEBエンジニア

WEBサイトやWEBサービスそのものを作る仕事。

未経験から目指す人がいちばん多いのがここですが、
**入口としては一番きつい部類です。**

人気が高いぶん、完全ノースキルでの直接応募はほぼ通りません。
3〜6ヶ月の学習とポートフォリオが前提になります。

逆に言えば、そこさえ用意できれば道は開けます。順番の問題です。

## 未経験からいきなりは、まず無理な職種

- AIエンジニア／機械学習エンジニア
- セキュリティエンジニア
- ITコンサルタント
- ゲームプログラマ
- PM／PL

これは「諦めろ」という話ではありません。**入口が違うだけです。**

AIをやりたいなら、まずインフラかWEBで実務経験を積み、
そこからPythonとデータ領域へ移る。
セキュリティならインフラで3年やってから資格を取る。

ゴールへの道はつながっています。

むしろ面接で
「将来はAIをやりたい。そのためにまずインフラで基礎を固めたい」
と言えると、計画性が評価されます。

## 職種を選ぶときの3つの判断軸

全部の情報を集めてから決めようとすると、いつまでも決まりません。
この3つに答えるだけで、選択肢は1〜2個に絞れます。

**1. 収入をいつから発生させたいか**

今すぐ必要 → インフラ
半年後でいい → WEB・Salesforce

**2. 夜勤・シフトを受け入れられるか**

NGなら、ヘルプデスクやクラウド系の日勤求人に絞る

**3. 平日に学習時間をどれだけ確保できるか**

1日1時間未満なら、WEBルートは正直きつい

## おわりに

「ITエンジニア」という一語で考えている限り、
入りやすさの差は見えてきません。

自分がどの入口に立っているのかが分かるだけで、
やるべきことはかなり具体的になります。

職種ごとの詳しい内容や、未経験求人の実例は
サイトのほうにまとめています。

https://hk8787.github.io/itsaiyou/

相談も無料で受けています。費用は一切かかりません。

# 記事2

## タイトル

```
未経験ITの1年目、手取りはいくらか。ごまかさずに書きます
```

## 本文

転職を考えるとき、最後に足を止めるのはだいたいお金です。

「やってみたいけど、生活できるのか」

ここが曖昧なまま進むと、入社後に苦しくなります。
なのに、はっきり数字を書いている記事が本当に少ない。

「年収◯百万円可能」みたいな求人票の話ではなく、
**手元に実際いくら残るのか**を書きます。

## 初年度の額面と、実際の手取り

未経験入社の月給は、**21〜25万円あたりがボリュームゾーン**です。

ここから社会保険料と税金が引かれるので、手取りはおおよそ8割。

- 月給21万円 → 手取り約16.5〜17万円
- 月給23万円 → 手取り約18〜18.5万円
- 月給25万円 → 手取り約19.5〜20万円

賞与がある会社なら、これに年2回分が乗ります。

ただし**入社初年度は査定期間が足りず、満額出ないことがほとんどです。**
1年目の年収は「月給×12＋少しの賞与」で見ておくと、あとでがっかりしません。

## 夜勤があると、ここが変わります

インフラ系のシフト勤務では深夜手当がつきます。

深夜割増は法律で**25%以上**と決まっています。
月に数回入るだけで2〜4万円変わることもある。

つまり、同じ月給21万円でも手取りが大きく違ってきます。

求人票の月給だけで比較すると実態を見誤るので、
面接で「手当込みで月いくらになるか」を必ず聞いてください。

## 前職より下がる人、上がる人

正直に書くと、**下がる人はそれなりにいます。**

特に、歩合のある営業、夜勤の多い運送や介護、
残業の多い職場から来た人は、一時的に落ちることが多い。

逆に上がりやすいのは、アルバイト・パートからの転換、
小売・飲食の正社員、地方の低賃金帯から来た人です。
社会保険や賞与が付くだけで、年収ベースでは改善するケースがあります。

## 大事なのは1年目ではなく3年後

ITは**実務年数がそのまま単価になる業界**です。
ここが他業種と決定的に違うところで、上がり方の形が違います。

- 1年目：月給21〜25万円。覚える期間。ここで焦って動かない
- 2〜3年目：月給25〜32万円。実務経験が値段になり、資格手当も乗る
- 3年目以降：社内で上げるか、経験を持って動くかの分岐点
- フリーランス：実務2〜3年が目安。単価が跳ねるのはここから

つまり**1〜2年目は投資期間**です。

ここを「今の給料」だけで判断すると、
いちばん割に合わないタイミングで辞めることになります。

## 転職前に必ず計算しておくこと

月にいくらあれば生活が回るか。

家賃・光熱費・通信費・食費・返済を足すだけです。5分で出ます。

この数字が手取り見込みを超えているなら、

- 条件を上げるか
- 夜勤ありの求人も視野に入れるか
- 学習期間のないルートを選ぶか

判断材料が一気に具体的になります。

逆にここが曖昧なまま「年収は高いほうがいい」と言っても、求人は絞り込めません。
誰だって高いほうがいいので、条件として機能しないんです。

## 貯金額で、選べるルートが変わります

学習期間を挟むルートは、その間の生活費が必要です。

貯金が2ヶ月分しかないなら、すぐ働き出せるインフラルート一択。
実家住まいで半年耐えられるなら、選択肢は一気に広がります。

**お金の話は足かせではなく、選択肢を絞り込む道具**だと思ってください。
先に出しておいたほうが、確実に早く決まります。

## おわりに

数字を見て「思ったより低い」と感じた人もいると思います。
それが正直なところです。

ただ、3年後の数字まで含めて判断してほしい。
1年目だけを見て決めるには、もったいない業界だと思っています。

職種ごとの年収レンジや、未経験求人の実例は
サイトのほうにまとめています。

https://hk8787.github.io/itsaiyou/

# 記事3

## タイトル

```
「未経験からITはやめとけ」を、一個ずつ検証してみた
```

## 本文

「未経験 IT」で調べると、必ず出てくるのが「やめとけ」という言葉です。

これ、**当たっている部分とそうでない部分が混ざっています。**
一緒くたにされているせいで、判断材料になっていない。

一個ずつ分けて見ていきます。

## 当たっている：1年目の年収は下がることがある

これは本当です。

未経験入社の初年度は月給21〜25万円あたりが中心。
前職が歩合の営業や夜勤の多い仕事だった場合、
一時的に下がる可能性は普通にあります。

上がるのは経験を積んだ後です。
ここを「数年の投資期間」と捉えられるかどうかが分かれ目になります。

**「やめとけ」と言う人の多くは、ここで辞めた人です。**

## 当たっている：インフラ系は夜勤・シフトがある

24時間動き続けるシステムを守る仕事なので、当然といえば当然です。

日勤固定の求人もありますが、数は限られ、競争率も上がります。

「夜勤は絶対に無理」なら、最初からそう言ったほうがいい。
求人の探し方自体が変わります。

## 当たっている：入社後も勉強は続く

資格を取って終わり、ではありません。
技術は数年で入れ替わるので、学び続けることが仕事の一部になります。

これを「しんどい」と取るか「学歴や過去の職歴ではなく、
今の努力が評価される」と取るかは人によります。

## 当たっている：最初の配属は地味

運用監視ならアラートの確認と一次対応。
開発なら既存コードの小さな修正から。

想像していた「バリバリ作る仕事」にはすぐには辿り着きません。

ここで腐らずに1〜2年続けられた人が、次のステージに行っています。

---

ここまでが「当たっている」側です。ここからは違います。

## 当たっていない：「学歴がないと無理」

**未経験枠は学歴不問の求人のほうが多いです。**

「大卒以上」で止まっている場合、
見ている求人の母集団が経験者向けになっている可能性が高い。

高卒・専門卒で諦めている人がかなりいますが、
単に見ている場所が違うだけ、というケースをよく見ます。

## 当たっていない：「30代は無理」

職種によります。

インフラ系とヘルプデスクは人手が足りていないので、
年齢で門前払いにはなりにくい。

きついのは、学習期間3〜6ヶ月が前提のWEBルートのほうです。
これは年齢というより、**その間の生活を支えられるか**の問題です。

## 当たっていない：「食いっぱぐれる」

ITは実務年数がそのまま市場価値になる業界です。

むしろ、学歴の影響が年々薄まっていく方向に働きます。
2〜3年やれば、フリーランスという選択肢も現実的に出てきます。

## 結局どう判断すればいいか

「やめとけ」の中身を分解すると、実質的な論点は1つです。

> **1〜2年目の投資期間を耐えられるか**

年収が一時的に下がり、地味な作業が続き、勉強も必要。
この期間を越えられる状況にいるかどうか。

ここが判断の全てだと思います。

貯金があるか、扶養する家族がいるか、
今の職場をいつまでに出る必要があるか。
このあたりが答えを決めます。

## それでも、やる価値があると思う理由

- 実務経験の年数がそのまま市場価値になる。学歴の影響が年々薄まる
- 求人が全国にあり、勤務地の自由度が高い。将来リモートも狙える
- 経験2〜3年でフリーランスという選択肢が現実的に出てくる
- 「未経験可」の入口が、他業界と比べて圧倒的に広い

最後の一つが、個人的にはいちばん大きいと思っています。

30代未経験で入れる業界は、そう多くありません。

## おわりに

「やめとけ」も「絶対やるべき」も、どちらも雑な結論です。

自分の状況に当てはめて、耐えられる期間があるかを見てください。
そこが分かれば、判断は自然に決まります。

職種ごとの入りやすさや、未経験求人の実例は
サイトのほうにまとめています。

https://hk8787.github.io/itsaiyou/

相談も無料です。「今は動かない」という結論でも構いません。

# 記事4

## タイトル

```
未経験の面接で「なぜIT業界なのか」に答えられない人へ
```

## 本文

未経験採用で、ほぼ100%聞かれる質問があります。

**「なぜIT業界なのですか」**

ここでつまずく人が本当に多い。
そして、つまずき方にはっきりした型があります。

## まず、落ちる答え

- 「手に職をつけたいと思ったからです」
- 「将来性がある業界だと思ったからです」
- 「在宅で働けるイメージがあるからです」
- 「全然分からないので、色々教えてもらいたいです」

なぜダメなのか、順番に書きます。

**「手に職」** → ITでなくてもいい理由です。
電気工事でも調理師でも成立してしまう。

**「将来性」** → 誰でも言えます。調べた形跡がゼロに見えます。

**「在宅」** → 待遇目当てと受け取られます。
しかも未経験の最初の配属で在宅はまずありません。

**「教えてもらいたい」** → 受け身。ほぼ確実に落ちます。

## 採用側が見ているもの

未経験採用で企業が見ているのは、スキルではありません。

**「入社後に自走して勉強し続けてくれるか」の一点です。**

未経験を採る企業は、教育コストを先に払ってから回収する前提で動いています。
だから「教えてもらう気満々の人」ではなく「勝手に伸びそうな人」を採る。

そして、それを測る質問が「なぜIT業界なのか」なんです。

この構造が分かると、答えるべきことが見えてきます。

## 通る答えの構造：3つのパーツ

通る答えは、だいたいこの3つでできています。

1. **きっかけ** — 自分の体験に紐づいた具体的なエピソード
2. **調べたこと** — 職種を比較して、なぜこの職種を選んだのか
3. **すでに始めていること** — 学習の実績。小さくても構いません

3番目が効きます。**すでに自分で動き始めている事実**が、
「自走できる」の何よりの証拠になるからです。

## 例：飲食業からインフラエンジニアを志望する場合

> 前職の店舗で予約システムが止まり、半日、紙とペンで回したことがありました。
> そのとき初めて、自分の仕事が誰かの作ったシステムの上で
> 成り立っていたと気づきました（**きっかけ**）。
>
> そこからIT業界を調べ、アプリを作る側とそれを動かし続ける側があると知り、
> あのとき自分が困ったのは「動かし続ける側」だったと分かって、
> インフラに関心を持ちました（**調べたこと**）。
>
> 現在はLinuxの学習サイトを1日1時間進めていて、
> 来月CCNAを受験します（**始めていること**）。

## 例：販売職からWEBエンジニアを志望する場合

> 店舗の売上を伸ばすためにSNS運用を任され、
> 投稿からECサイトへの導線を自分で考えた経験があります。
> そのとき、サイトの中身は自分では変えられないのがもどかしかった（**きっかけ**）。
>
> 作る側に回りたいと考え、フロントエンドとバックエンドの違いを調べ、
> まず目に見える部分から入りたいと思いました（**調べたこと**）。
>
> 今はProgateでHTML/CSSとJavaScriptを一周し、
> 簡単なページを自分で作っています（**始めていること**）。

## 自分の答えを作る手順

1. 過去の仕事や生活の中で、ITが関わって困った／助かった場面を1つ思い出す
2. その場面が、どの職種の領域だったのかを調べる
3. 今日から何か1つ学習を始める（無料で構いません。事実さえあればいい）
4. 上の3パーツを繋げて、**90秒で話せる長さ**に削る

3番が一番大事です。
面接までに時間がなくても、**今日始めれば今日から事実になります。**

## エピソードが思いつかない人へ

無理に劇的な話を作る必要はありません。

- 「スマホゲームの裏側が気になった」
- 「親のPCを直したら喜ばれた」

この程度で十分です。

大事なのは、借り物ではなく自分の言葉であること。
**作り話は深掘りされた瞬間に崩れます。**
